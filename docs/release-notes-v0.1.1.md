# CommandCode Provider v0.1.1

修复 v0.1.0 经 CPA 插件商店安装后“已配置、已启用，但未注册、未生效”的问题。仅修改插件，不修改 CPA 核心。

## 修复

- 接受并忽略 CPA 在生命周期配置中透传的 `store` 元数据，避免 `plugin.register` / `plugin.reconfigure` 返回 `invalid config yaml`。
- 保持业务配置严格校验：未知顶层字段仍拒绝，商店版本、来源及扩展元数据不影响传输模式或上游地址。
- 添加商店注册与配置热重载回归测试；全部真实宿主测试使用版本化动态库文件名及商店配置形状。

## 升级

- 刷新 CPA 插件商店，升级或重新安装 **v0.1.1**。保留现有插件设置与凭据，无须删除 `store` 或修改 CPA。
- 若此前为临时恢复删除了 `store`，通过商店安装 v0.1.1，让 CPA 重建新版本元数据；不要原样恢复指向 v0.1.0 的旧元数据。
- `registry.json` 源地址不变，继续跟随最新正式 Release。

## 验证与限制

- Go test/vet/race、42 项 UI 测试、23 项资产校验测试及打包检查。
- CPA v8.0.23 + 本地合成上游：21 项顶层集成测试，涵盖商店注册、配置热重载及既有三协议/两模式/流式与非流式链路。
- 发布流程对准确 tag 重新执行验证，并构建 linux/amd64、linux/arm64、macOS/arm64 原生资产与 `checksums.txt`。
- 未调用真实上游，未使用真实凭据；套餐权限、配额、缓存、费用及 ABI 限制与 v0.1.0 相同。
