# CommandCode Provider v0.2.0

新增每凭据独立传输模式：同一个 CPA 凭据池可以混用 `cli` 与 `provider`。仅修改插件，不修改 CPA 核心，也不增加独立调度器。

## 新增与修复

- 物理 auth JSON 支持根级 `mode: "cli"` 或 `"provider"`；执行和模型发现按所选凭据解析模式，并绑定当前请求快照，不改变共享配置。
- 导入表单支持选择模式，凭据列表支持逐条修改模式并重新读取确认；新增 `PATCH /keys`，只改 `mode`，保留原凭据字段、未知 JSON 字段及精确数字。
- `GET /keys` 增加 `mode`、`mode_source` 与 `mode_error`；settings 增加 `default_mode`、`mode_scope: "auth"` 及两种目录状态。
- 手动模型元数据由两种模式共享，但按实际凭据模式判定资格；Provider-only 与 CLI-only 模型仅由对应凭据执行，避免模型发布与实际路由不一致。
- 严格拒绝非法、null、重复、未知或大小写变体管理字段及尾随 JSON；外来凭据不能通过此插件修改，错误不回显凭据。
- 保存后未确认、目标消失或读取失败时，管理页保留原列表与选择，不把“已提交”误报为“已生效”。

## 升级与兼容

1. 在 CPA 插件商店刷新源并升级到 **v0.2.0**；源地址和插件 ID 不变。
2. 保留现有配置与凭据，无须重新导入。没有根级 `mode` 的旧记录继续采用 YAML `mode`（缺省 `cli`）。
3. YAML `mode` 现在仅是旧记录及未传模式导入请求的默认值，不覆盖已有显式配置；需批量改模式时，应逐条更新凭据。
4. 管理页导入下拉默认选 CLI，显式提交本次选择；重复导入仍 skipped，不修改既有凭据模式。

插件不检测套餐，也不因 `403 upgrade_required` 或其他错误自动切换模式。Go 套餐仍没有 Provider API 权限，应由管理员显式选用适合该凭据的模式。

## 验证与限制

- Go test/vet/race、54 项 UI 测试、23 项资产校验及打包检查。
- CPA v8.0.23 + 本地合成上游：27 项顶层集成测试，包含三协议/两模式矩阵、混合池、专属模型、热修改及重启持久化、非法模式零上游调用与外来凭据隔离。
- 新增每凭据模式集成测试连续重复 5 轮通过；热改后、执行后及重启后均检查精确 JSON 整数 `9007199254740993` 保留。
- 发布流程对准确 tag 重新验证，原生构建 linux/amd64、linux/arm64、macOS/arm64，并提供 `checksums.txt`。
- 全部运行时验收使用合成凭据与 loopback 上游；未验证真实服务的套餐、缓存命中率或扣费。CPA 原生 ABI 与 Observer 未定价限制保持不变。
